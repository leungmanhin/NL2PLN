1. Entity classification and type membership  
   Recap: English asserts that an individual belongs to a kind, category, or role.  
   Chainer features to exercise: Unary classification fact; Class membership idioms; `STV`  
   Constraint templates: (none)

2. Named entities and proper reference  
   Recap: Proper names and unique labels refer to particular entities.  
   Chainer features to exercise: Recommended entity IDs; Names as ordinary facts; Binary relation fact  
   Constraint templates:  
   - If the surface name is preserved, include an ordinary `(Name entity surfaceName)` fact with truth value `(STV 1.0 1.0)`.  
   - Do not rely on ambiguous bare constants when the example distinguishes multiple entities with the same name.

3. Common nouns and sortal constraints  
   Recap: Common nouns introduce entity kinds and constrain argument roles.  
   Chainer features to exercise: Unary classification fact; Ordinary predicates; Multi-premise rule  
   Constraint templates: (none)

4. Properties and attributes  
   Recap: English ascribes qualities, materials, colors, sizes, and similar attributes.  
   Chainer features to exercise: Unary classification fact; Ordinary predicates; `STV`  
   Constraint templates:  
   - For appearance/hedging examples such as “seems tired”, the target property fact should use `(STV s c)` where either `0.0 < s < 1.0` or `0.0 < c < 1.0`, not `(STV 1.0 1.0)`.

5. Gradable properties and degree  
   Recap: Gradable adjectives and adverbs express scalar values and degree modification.  
   Chainer features to exercise: Distribution values; `PointMass`; `ParticleFromNormal`; `ParticleFromPairs`; Rule over uncertain numeric values; `GreaterThan`; `MapDist`  
   Constraint templates:  
   - Numeric or scalar degree values must be represented as distribution terms inside propositions, e.g. `(HeightDist entity (PointMass n))`, not as `STV` strength.  
   - Threshold-derived gradable predicates such as “tall”, “too narrow”, or “very high” should be derived by an `Implication` whose `Premises` include `GreaterThan` over a distribution.  
   - Approximate or uncertain scalar values should use `ParticleFromNormal` or `ParticleFromPairs`, not `(PointMass n)`.

6. Non-gradable and categorical properties  
   Recap: Some predicates express binary or conventional categories rather than scales.  
   Chainer features to exercise: Unary classification fact; Ordinary predicates; `STV`; `Not` when explicit truth complement is intended  
   Constraint templates: (none)

7. Relational nouns and inherent relations  
   Recap: Nouns such as sister, student, owner, and part imply another participant.  
   Chainer features to exercise: Binary relation fact; Multi-premise rule; Multi-conclusion rule  
   Constraint templates:  
   - If a relational noun licenses role/type inferences, use an `Implication` with shared variables in `Premises` and `Conclusions` rather than a single monolithic predicate only.

8. Possession and ownership  
   Recap: Possessives and have-constructions express ownership, control, association, or belonging.  
   Chainer features to exercise: Binary relation fact; Existential quantification via fresh constants; Cardinal quantifiers via `FoldAll`/`FoldAllValue`  
   Constraint templates:  
   - For “has/owns N Xs” examples with explicit counts, derive or query the count using `FoldAll` or `FoldAllValue`; do not encode the numeral only in a predicate name such as `HasThreeOffices`.

9. Identity, equality, and distinctness  
   Recap: English can state that two descriptions co-refer or that two entities are different.  
   Chainer features to exercise: Entity identity model; Recommended entity IDs; Ordinary predicates; `BiImplication` if explicit same-as rules are defined  
   Constraint templates:  
   - Do not use unsupported built-ins such as `=`, `Equal`, or `Distinct` unless they are ordinary application-defined predicates with explicit rules.  
   - True co-reference should normally be represented by reusing the same entity constant.

10. Existence and absence  
   Recap: English asserts or denies that entities, events, or states exist or are present.  
   Chainer features to exercise: Existential quantification via fresh constants; Binding retrieval with query variables; `Not`; `FoldAllValue` for absence/count reasoning  
   Constraint templates:  
   - Existential assertions should introduce a fresh constant and assert facts about it; existential questions should use a query variable such as `(: $prf (Person $x) $tv)`.  
   - Do not use `Not` to mean “not found”; `Not` may be used only as truth complement over an inner expression that has evidence.

11. Definiteness and indefiniteness  
   Recap: Articles and determiners signal newness, familiarity, uniqueness, or identifiability.  
   Chainer features to exercise: Recommended entity IDs; Existential quantification via fresh constants; Binding retrieval with query variables  
   Constraint templates: (none)

12. Demonstratives and deixis  
   Recap: Expressions like this, that, here, and there depend on context and salience.  
   Chainer features to exercise: Pronoun/deixis resolution before generation; Recommended entity IDs  
   Constraint templates:  
   - Do not assert facts about literal constants such as `this`, `that`, `here`, or `there` unless the application explicitly defines them; resolve them to concrete constants first.

13. Mass nouns, count nouns, and substance reference  
   Recap: English distinguishes countable individuals from masses and substances.  
   Chainer features to exercise: Distribution values; `PointMass`; Cardinal quantifiers via `FoldAll`/`FoldAllValue`; Ordinary predicates  
   Constraint templates:  
   - Count-noun numerical examples should use individual entities plus `FoldAll`/`FoldAllValue` when a count is derived.  
   - Mass/substance quantity examples should represent amounts as distribution-valued terms, not as `STV` strength.

14. Measures, units, and quantities  
   Recap: Noun phrases can specify measured length, volume, weight, price, or amount.  
   Chainer features to exercise: Distribution values; `PointMass`; `ParticleFromNormal`; `ParticleFromPairs`; `GreaterThan`; `MapDist`; `Map2Dist`  
   Constraint templates:  
   - Exact measurements should use a distribution term such as `(PointMass n)` inside the proposition and a separate truth value such as `(STV 1.0 1.0)`.  
   - Approximate measurements should use `ParticleFromNormal` or `ParticleFromPairs`.  
   - Comparisons against measured thresholds should use `GreaterThan` over distributions.

15. Plurality and number  
   Recap: Singular and plural marking distinguishes one entity from multiple entities.  
   Chainer features to exercise: Cardinal quantifiers via `FoldAll`/`FoldAllValue`; Existential quantification via fresh constants; Ordinary predicates  
   Constraint templates:  
   - Numeral-driven plural examples should introduce the appropriate individual constants or derive a count with `FoldAll`/`FoldAllValue`; do not represent plurality solely by a plural predicate name.

16. Collective and distributive readings  
   Recap: Plural subjects may act as a group or as individual members.  
   Chainer features to exercise: Set membership predicates; Multi-premise rule; Universal quantification via rules with variables; `FoldAll`  
   Constraint templates:  
   - Distributive readings with “each/every” should use an `Implication` with a member variable shared between `Premises` and `Conclusions`.  
   - Collective readings should represent the group as an entity or event participant, not automatically assert the predicate of every member.

17. Part-whole and meronymy

18. Set membership and inclusion

   Constraint templates:

   - Prevention should not use `Not` as negation-as-failure; use an explicit prevention predicate, or use `Not` only over an evidenced inner proposition.

40. Frequency and habitual aspect

   Chainer features to exercise: `STV`; `Implication`; `FoldAll`; `Compute` for periodic schedules  
   Constraint templates:  
   - Frequency adverbs such as “often”, “usually”, or “rarely” should use a target proposition or rule truth value `(STV s c)` with `0.0 < s < 1.0`, not `(STV 1.0 1.0)`.

41. Iteration and repetition  
   Recap: English can describe events occurring multiple times or again.  
   Chainer features to exercise: Cardinal quantifiers via `FoldAll`/`FoldAllValue`; `Compute`; Ordinary predicates  
   Constraint templates:  
   - Exact repetition counts such as “three times” should be represented by distinct event instances plus a derived count using `FoldAll`/`FoldAllValue`, or by an explicit count-valued proposition.

42. Existential quantification  
   Recap: Determiners and pronouns assert that at least one suitable entity exists.  
   Chainer features to exercise: Existential quantification via fresh constants; Binding retrieval with query variables  
   Constraint templates:  
   - Existential assertions must introduce a fresh constant and assert its descriptive facts.  
   - Existential queries must use a variable in the proposition pattern, e.g. `(: $prf (Bird $x) $tv)`, not an unsupported `Exists`.

43. Universal quantification  
   Recap: English states that a claim holds for all members of a set.  
   Chainer features to exercise: Universal quantification via rules with variables; `Implication`; Multi-premise rule  
   Constraint templates:  
   - Universal statements must be represented with an `Implication` whose variables in `Conclusions` also occur in `Premises`; do not use an unsupported `ForAll`.

44. Cardinality and exact number  
   Recap: Numerals specify exact, minimum, maximum, or bounded counts.  
   Chainer features to exercise: Cardinal quantifiers via `FoldAll`; `FoldAllValue`; `GreaterThan`; Distribution values  
   Constraint templates:  
   - Derived counts should use `FoldAll` or `FoldAllValue`, not unsupported operators such as `Exactly`, `AtLeast`, or `AtMost`.  
   - “At least N” over an uncertain count distribution should be encoded with `GreaterThan countDist N-1`.  
   - Exact deterministic counts may be represented by a count-valued proposition or a `FoldAll` result queried against the numeral.

45. Proportional and fractional quantification  
   Recap: Expressions describe proportions, fractions, percentages, or parts of a group.  
   Chainer features to exercise: `FoldAll`; `FoldAllValue`; `Compute`; `GreaterThan`; Distribution values  
   Constraint templates:  
   - Proportion examples should derive numerator and denominator counts using `FoldAll`/`FoldAllValue`.  
   - Fraction or percentage thresholds should use `Compute` to calculate the threshold and `GreaterThan` for distribution comparisons where applicable.  
   - Do not use unsupported built-ins such as `Most`, `Majority`, `Half`, or `Percent`.

46. Indefinite and vague quantification  
   Recap: English uses imprecise quantity expressions such as many, few, several, enough, and some.  
   Chainer features to exercise: Cardinal quantifiers via `FoldAll`/`FoldAllValue`; `GreaterThan`; `STV`; Domain-specific threshold rules  
   Constraint templates:  
   - Vague quantifiers such as “many”, “few”, or “enough” should be encoded through an explicit threshold rule using `FoldAll`/`FoldAllValue` and usually `GreaterThan`; do not use unsupported operators named `Many`, `Few`, or `Enough` as built-ins.  
   - Vague threshold rules may use `(STV s c)` where either `0.0 < s < 1.0` or `0.0 < c < 1.0`.

47. Negative quantification  
   Recap: Determiners and pronouns combine quantification with negation, as in no, nobody, and nothing.  
   Chainer features to exercise: `Not`; Cardinal quantifiers via `FoldAllValue`; Ordinary predicates  
   Constraint templates:  
   - Do not use `Not` to mean absence of a matching proof; `Not` may be used only as truth complement over an evidenced expression.  
   - Quantified absence should be represented by explicit negative/absence predicates or by count reasoning with `FoldAllValue`, not by an unsupported `No` operator.

48. Exceptives and inclusion modifiers  
   Recap: Expressions such as except, only, also, and besides include or exclude alternatives.  
   Chainer features to exercise: Multi-premise rule; `Not` only for explicit complement; Ordinary predicates; Set membership predicates  
   Constraint templates:  
   - Exceptive rules should represent exceptions explicitly as ordinary predicates in `Premises`; if `Not` is used for “not an exception”, the inner exception predicate must have evidence.  
   - Do not use unsupported built-ins such as `Except` or `Only` unless defined as ordinary predicates with rules.

49. Negation  
   Recap: English denies propositions, predicates, events, quantities, or constituents.  
   Chainer features to exercise: `Not`; `STV`; Scope by S-expression structure  
   Constraint templates:  
   - `Not` must be used only as truth-value complement: if the inner expression has `(STV s c)`, the negated expression should have strength `1 - s` and confidence `c`.  
   - Do not use `Not` for “unknown” or “not found”.

50. Lexical negation and antonymy  
   Recap: Some words encode negative or opposite meanings without explicit sentential negation.  
   Chainer features to exercise: Ordinary predicates; `Not` only when complement semantics is intended; `Implication` for antonym rules  
   Constraint templates:  
   - Lexically negative predicates such as “incorrect”, “empty”, or “failed” should normally be ordinary predicates; translate them as `Not` only when the example explicitly requires truth complement of an evidenced positive predicate.

51. Modality of ability  
   Recap: Can and able to describe capacities, skills, or possibilities of action.  
   Chainer features to exercise: Ordinary predicates; `Implication`; `STV` for uncertain ability  
   Constraint templates: (none)

52. Modality of possibility and probability  
   Recap: English expresses that something may, might, could, or is likely to be true.  
   Chainer features to exercise: `STV`; `LikelierThan`; Ordinary predicates  
   Constraint templates:  
   - Possibility/probability claims should assign the target proposition `(STV s c)` with `0.0 < s < 1.0` or `0.0 < c < 1.0`, not `(STV 1.0 1.0)`.  
   - “More likely than” comparisons should use `LikelierThan exprA exprB`.

53. Modality of necessity and obligation  
   Recap: Must, have to, need to, and should express requirements, necessities, or duties.  
   Chainer features to exercise: Ordinary predicates; `Implication`; `STV` for defeasible rules  
   Constraint templates:  
   - Deontic obligation should be represented with predicates such as `Obligatory`, `Required`, or domain-specific equivalents, not by asserting that the required action occurred.  
   - General obligation rules should use `Implication`.

54. Modality of permission and prohibition  
   Recap: English states what is allowed, forbidden, or authorized.  
   Chainer features to exercise: Ordinary predicates; `Implication`; `Not` only for explicit truth complement  
   Constraint templates:  
   - Permission should be represented by an `Allowed`/`Permitted`-style ordinary predicate, not by asserting the permitted event as actual.  
   - Prohibition should use an explicit `Forbidden` predicate or `Not (Allowed ...)` only when the inner `Allowed` expression has evidence.

55. Epistemic versus deontic modality  
   Recap: The same modal forms can express inference or obligation depending on context.  
   Chainer features to exercise: `STV`; Ordinary predicates; `Implication`  
   Constraint templates:  
   - Epistemic “may/must/likely” should affect the truth value of the embedded proposition with `(STV s c)` where uncertainty is reflected by `s < 1.0` or `c < 1.0`.  
   - Deontic “may/must” should produce permission/obligation predicates or rules, not a direct assertion of event occurrence.

56. Conditionals and if-then relations  
   Recap: Conditional clauses state dependencies between antecedents and consequents.  
   Chainer features to exercise: `Implication`; `Premises`; `Conclusions`; Multi-premise rule; `BiImplication` for iff  
   Constraint templates:  
   - If-then examples must use an `Implication` atom with antecedents in `Premises` and consequents in `Conclusions`.  
   - Variables in `Conclusions` should also occur in `Premises` unless a deliberate fresh constant is introduced.  
   - If-and-only-if examples should use `BiImplication`.

57. Counterfactual conditionals  
   Recap: English describes hypothetical or contrary-to-fact dependencies.  
   Chainer features to exercise: `Implication`; `STV`; Ordinary predicates for hypothetical context  
   Constraint templates:  
   - Counterfactual examples should not assert the antecedent or consequent as ordinary factual ground facts unless the text separately states them.  
   - If represented as a rule, the counterfactual dependency should use `Implication` with a non-default truth value such as `(STV s c)` where `c < 1.0`.

58. Comparison of greater, lesser, and equal degree  
   Recap: Comparative constructions order entities or events on scales.  
   Chainer features to exercise: Distribution values; `GreaterThan`; `LikelierThan` for likelihood comparisons  
   Constraint templates:  
   - Degree comparisons such as “taller than” should compare distribution-valued measurements with `GreaterThan distA distB`.  
   - “Less than” comparisons should reverse the arguments to `GreaterThan` where possible.  
   - Do not use `GreaterThan` for arbitrary scalar constants unless they are represented as distributions.

59. Superlatives and extremal comparison  
   Recap: Superlatives identify maximal or minimal members of a comparison class.  
   Chainer features to exercise: `GreaterThan`; `FoldAll`; Distribution values; Ordinary predicates  
   Constraint templates:  
   - Superlative examples should not use unsupported built-ins such as `Max`, `Min`, or `Superlative` unless application-defined.  
   - If derived, extremal status should be supported by pairwise `GreaterThan` comparisons or explicit ranking/count rules over the comparison class.

60. Similarity and difference  
   Recap: English compares entities by likeness, shared properties, or contrast.  
   Chainer features to exercise: Ordinary predicates; Entity identity model; `STV` for graded similarity

61. Conjunction  
   Recap: English combines entities, predicates, clauses, and propositions with and.  
   Chainer features to exercise: `And`; Multi-premise rule; Multi-conclusion rule  
   Constraint templates:  
   - Conjunctive queries should use `And` with each conjunct as a child expression.  
   - Rules with conjunctive antecedents should prefer multiple expressions inside `Premises` rather than a single monolithic predicate.  
   - Do not rely on an asserted `(And A B)` alone as a replacement for separately asserting both `A` and `B`.

62. Disjunction  
   Recap: English expresses alternatives with or and either-or.  
   Chainer features to exercise: `Or`; `STV`; Ordinary predicates for alternatives  
   Constraint templates:  
   - Use `Or` only when the intended proof should exercise the chainer’s compound disjunction behavior.  
   - In default PLN mode, do not expect evidence for `A` alone to prove `(Or A B)` by simple introduction.  
   - For “maybe A or B”, prefer separate uncertain alternatives with `STV` rather than using `Or` as a mere uncertainty marker.

63. Coordination of unlike constituents  
   Recap: English can coordinate unlike semantic types when they share a function.  
   Chainer features to exercise: `And`; Ordinary predicates; Multi-premise rule  
   Constraint templates: (none)

64. Scope interactions  
   Recap: Quantifiers, negation, modals, and other operators can take different scopes.  
   Chainer features to exercise: Scope by S-expression structure; `Not`; `Implication`; Query variables  
   Constraint templates:  
   - `Not` scopes only over its immediate child expression.  
   - Do not introduce unsupported nested quantifier operators such as `ForAll` or `Exists`; use rules, variables, and expression structure.

65. Propositional attitudes  
   Recap: Verbs such as believe, know, think, hope, and doubt relate agents to embedded propositions.  
   Chainer features to exercise: Ordinary predicates with embedded proposition terms; `STV`  
   Constraint templates:  
   - Non-factive attitudes such as believe, think, hope, fear, or doubt should not by themselves assert the embedded proposition as true.  
   - The expected query/proof should target the attitude predicate unless the embedded content is independently asserted.

66. Desire, intention, and preference

   Chainer features to exercise: Ordinary predicates; `LikelierThan` only for likelihood, not preference; `Implication` for goal-driven rules

67. Knowledge and factivity  
   Recap: Some predicates presuppose or entail the truth of their complements, while others do not.  
   Chainer features to exercise: Ordinary predicates with embedded propositions; Multi-conclusion rule; `Implication`  
   Constraint templates:  
   - Factive predicates such as “knows” or “realized” should support both an attitude fact and the embedded proposition, either by separate assertions or by an `Implication`.  
   - Non-factive predicates such as “thinks” should not automatically derive the embedded proposition.

68. Communication and speech reports  
   Recap: English reports saying, asking, promising, warning, and other communicative acts.  
   Chainer features to exercise: Ordinary predicates with embedded proposition terms; `STV`; `Implication` for report-based evidence rules  
   Constraint templates:  
   - Speech-report predicates such as “said that” should not automatically assert the reported content as true.  
   - If the report is treated as evidence, use an explicit `Implication` from the report predicate to the reported proposition with non-default `(STV s c)` where `s < 1.0` or `c < 1.0`.

69. Questions and interrogatives  
   Recap: English asks for truth values, entities, quantities, times, places, reasons, or choices.  
   Chainer features to exercise: Required query envelope; Binding retrieval; Retrieve truth values; Compound-expression query; Query an aggregate directly  
   Constraint templates:  
   - All queries must have the envelope `(: $prf typePattern $tv)` with a variable in the proof slot.  
   - Wh-questions should use variables in `typePattern` for requested bindings.  
   - Yes/no questions should query the ground proposition and retrieve `$tv`.

70. Imperatives and directives  
   Recap: Imperatives issue commands, requests, instructions, or permissions.  
   Chainer features to exercise: Ordinary predicates; `Implication`; Deontic predicates  
   Constraint templates:  
   - Imperatives should be represented as command/request/obligation predicates or rules, not as assertions that the commanded action occurred.

71. Reasons and explanations  
   Recap: English expresses why something happens or why someone acts.  
   Chainer features to exercise: `Implication`; Multi-premise rule; Ordinary predicates  
   Constraint templates:  
   - General explanatory dependencies should use `Implication` with explanatory conditions in `Premises` and explained outcomes in `Conclusions`.

72. Focus-sensitive expressions  
   Recap: Words such as only, even, also, and too depend on focused alternatives.  
   Chainer features to exercise: Ordinary predicates; Set membership predicates; `Not` only for explicit complement; `FoldAll` for exhaustivity/counts

   - Exhaustive “only” readings should not be represented by an unsupported `Only` operator; use explicit alternative/exclusion predicates or count/set rules.

73. Anaphora and pronoun reference  
   Recap: Pronouns and anaphoric expressions refer back to discourse entities, events, or propositions.  
   Chainer features to exercise: Pronouns resolved before generation; Recommended entity IDs  
   Constraint templates:  
   - Do not assert facts about literal constants such as `he`, `she`, `it`, `they`, `I`, or `you` unless the application explicitly defines them.  
   - Resolved anaphors should reuse the antecedent’s constant.

74. Reflexives and binding  
   Recap: Reflexive pronouns require suitable antecedents, often locally.  
   Chainer features to exercise: Variables; Ordinary predicates; Entity identity model  
   Constraint templates:  
   - Reflexive arguments should reuse the same entity constant or variable as the antecedent, e.g. `(Praised alice alice)` or `(Praised $x $x)`.

75. Discourse reference and accessibility  
   Recap: Later expressions can depend on entities introduced earlier in discourse.  
   Chainer features to exercise: Existential quantification via fresh constants; Recommended entity IDs; Universal quantification via rules with variables  
   Constraint templates:  
   - An introduced indefinite should receive a fresh constant, and later definite/anaphoric references to it should reuse that constant.  
   - Donkey-style conditionals should use shared variables across `Premises` and `Conclusions`, not unlinked fresh variables.

76. Relative clauses  
   Recap: Relative clauses restrict or add information about nouns.  
   Chainer features to exercise: `And`; Multi-premise rule; Binding retrieval  
   Constraint templates:  
   - Restrictive relative clauses should combine noun and relative-clause conditions with `And` in queries or as multiple `Premises` in rules.

77. Restrictive versus appositive modification  
   Recap: Some modifiers narrow reference, while others add parenthetical information.  
   Chainer features to exercise: `And`; Multi-premise rule; Ordinary predicates  
   Constraint templates:  
   - Restrictive modifiers should appear as additional query/rule constraints, e.g. `And` children or multiple `Premises`.  
   - Appositive modifiers should be represented as separate facts about the already identified entity, not as required filters for identifying it.

78. Complement clauses  
   Recap: Clauses can function as arguments of verbs, adjectives, or nouns.  
   Chainer features to exercise: Ordinary predicates with embedded proposition terms; `STV`  
   Constraint templates: (none)

79. Control constructions  
   Recap: An unspoken infinitival subject is understood from another argument.  
   Chainer features to exercise: Variables; Multi-premise rule; Ordinary predicates  
   Constraint templates:  
   - Subject-control and object-control examples should reuse the controller’s constant or variable in the embedded predicate.

80. Raising constructions  
   Recap: The syntactic subject of a raising predicate belongs semantically to an embedded predicate.  
   Chainer features to exercise: `STV`; Ordinary predicates with embedded proposition terms  
   Constraint templates:  
   - Raising predicates expressing appearance or likelihood should reflect uncertainty on the embedded proposition with `(STV s c)` where `s < 1.0` or `c < 1.0`, rather than asserting only an unrelated surface-subject predicate.

81. Ellipsis and omitted material  
   Recap: English often leaves understood material unspoken and recoverable from context.  
   Chainer features to exercise: Context resolution before generation; Ordinary predicates  
   Constraint templates:  
   - Generated expressions should contain the recovered predicate and arguments explicitly; do not leave placeholder constants for omitted material.

82. Ambiguous attachment  
   Recap: Modifiers can attach to different constituents, changing meaning.  
   Chainer features to exercise: Ordinary predicates; Multiple candidate analyses if ambiguity is retained  
   Constraint templates: (none)

83. Preposition polysemy  
   Recap: Prepositions have spatial, temporal, causal, possessive, topical, and other senses.  
   Chainer features to exercise: Ordinary predicates; Binary relation fact  
   Constraint templates: (none)

84. Idioms and conventionalized meanings  
   Recap: Idioms have meanings not predictable from their parts.  
   Chainer features to exercise: Ordinary predicates; Entity/event representation with ordinary constants  
   Constraint templates:  
   - Idiomatic examples should map to the conventional meaning predicate, not to a forced compositional analysis of the literal words.

85. Metaphor and metonymy  
   Recap: English uses one domain or associated entity to refer to another.  
   Chainer features to exercise: Recommended entity IDs; Ordinary predicates; Name facts  
   Constraint templates: (none)

86. Presupposition triggers  
   Recap: Certain words imply background assumptions.  
   Chainer features to exercise: Multi-conclusion rule; `Implication`; Ordinary predicates  
   Constraint templates:  
   - Presupposed content should be represented as a separate fact or as a conclusion of an explicit rule, not hidden inside a monolithic predicate only.

87. Implicative and implicature-like predicates  
   Recap: Some verbs imply success, failure, or nonoccurrence of an embedded event.  
   Chainer features to exercise: `Implication`; Multi-conclusion rule; `Not` only for truth complement  
   Constraint templates:  
   - “Managed to V” should support deriving the embedded `V` proposition via assertion or `Implication`.  
   - “Failed to V” or “avoided V” should not use `Not` as absence-of-proof; use an explicit failure/avoidance predicate or `Not` only over evidenced `V`.

88. Adversative and concessive relations  
   Recap: English expresses contrast between expected and actual outcomes.  
   Chainer features to exercise: `And`; Ordinary predicates; `Implication` for expectation rules  
   Constraint templates: (none)

89. Alternative and exhaustive meanings  
   Recap: Some constructions select among alternatives or exclude unmentioned options.  
   Chainer features to exercise: `Or`; `Not` only for explicit complement; Ordinary predicates; Set membership predicates  
   Constraint templates:  
   - Exclusive alternatives require explicit exclusion/mutual-incompatibility predicates or rules; `Or` alone does not encode exclusivity.  
   - In default PLN mode, do not rely on simple or-introduction for `Or`.

90. Probability, uncertainty, and evidential strength  
   Recap: English marks confidence, rumor, appearance, uncertainty, or evidence.  
   Chainer features to exercise: `STV`; `LikelierThan`; `Not` for complement of uncertain truth  
   Constraint templates:  
   - Evidential or uncertainty markers such as “apparently”, “probably”, “seems”, or “rumor has it” should use `(STV s c)` where either `0.0 < s < 1.0` or `0.0 < c < 1.0`, not `(STV 1.0 1.0)`.  
   - Relative probability claims should use `LikelierThan exprA exprB`.

91. Evaluation and sentiment  
   Recap: English expresses judgments, attitudes, desirability, importance, or sentiment.  
   Chainer features to exercise: Ordinary predicates; `STV` for uncertain or subjective evaluation  
   Constraint templates: (none)

92. Norms, rules, and social roles  
   Recap: English states what is required, permitted, forbidden, customary, or appropriate.  
   Chainer features to exercise: `Implication`; Multi-premise rule; Ordinary deontic predicates; `STV` for defeasible norms  
   Constraint templates:  
   - General norms should be represented by `Implication` rules from role/context premises to `Required`/`Allowed`/`Forbidden`-style conclusions.  
   - Normative claims should not assert that the norm-following action actually occurred.

93. Numerical approximation and vagueness  
   Recap: English expresses inexact numerical values and vague thresholds.  
   Chainer features to exercise: Distribution values; `ParticleFromNormal`; `ParticleFromPairs`; `PointMass`; `GreaterThan`  
   Constraint templates:  
   - Approximate numerals such as “about twenty” or “nearly an hour” should use `ParticleFromNormal` or `ParticleFromPairs`, not a bare exact `PointMass`.  
   - Threshold claims such as “over six feet” should use `GreaterThan` over a distribution-valued measurement.

94. Ordinals and ranking  
   Recap: Ordinal expressions identify position in an ordered sequence.  
   Chainer features to exercise: Ordinary predicates; `GreaterThan` for score-derived rankings; `FoldAll` for derived ranks  
   Constraint templates: (none)

95. Event nominalization  
   Recap: Nouns can denote events, processes, or results derived from verbs.  
   Chainer features to exercise: Ordinary predicates; Binary relation fact; Recommended entity IDs  
   Constraint templates: (none)

96. Subsective, intersective, and intensional adjectives  
   Recap: Modifiers differ in whether they preserve category membership or introduce intensional readings.  
   Chainer features to exercise: Multi-conclusion rule; `Implication`; Ordinary predicates  
   Constraint templates:  
   - Intersective modifiers such as “red car” should support both the noun classification and the property fact.  
   - Intensional or non-intersective modifiers such as “former senator” or “alleged thief” should not automatically derive the unmodified class unless an explicit rule licenses it.

97. Quotation, mention, and language use  
   Recap: English can use words to refer to expressions themselves rather than their usual denotations.  
   Chainer features to exercise: Ordinary predicates; Recommended entity IDs; Name facts  
   Constraint templates: (none)

98. Polarity items and licensing  
   Recap: Some expressions are licensed only under negation, questions, conditionals, or similar environments.  
   Chainer features to exercise: `Not`; Query envelope; `Implication` for conditional licensing contexts  
   Constraint templates:  
   - Polarity licensing itself should be handled by the language layer; do not introduce unsupported polarity-item operators into the chainer expression.
