
# PeTTaChainer surface language for `add_atom()` and `query()`

This reference describes the expression strings an external caller should pass directly to the Python API:

- `handler.add_atom("<statement>")`
- `handler.query("<query>", steps=...)`

The strings are MeTTa-style S-expressions. Do not include outer command wrappers such as `!(compileadd ...)`, `!(compileadd-mine ...)`, `!(query ...)`, or a KB name inside the string passed to the Python API.

---

## 1. Expression format

### 1.1 Statement form for `add_atom`

Template:

    (: proof-id type tv)

Meaning:

- `proof-id` is an atom or expression naming this asserted proof/fact/rule.
- `proof-id` must not be a variable.
- `type` is the proposition, fact pattern, or rule being asserted.
- `tv` is a supported non-variable truth/value object.

Examples:

    (: d1 (Dog fido) (STV 1.0 1.0))

    (: h1 (HeightDist group1 alice (PointMass 160.0)) (STV 1.0 1.0))

    (: r1
       (Implication
          (Premises (Dog $x))
          (Conclusions (Animal $x)))
       (STV 1.0 1.0))

The `type` slot may contain arbitrary predicate expressions such as `(Dog fido)`, `(Owns alice dog1)`, `(AtTime (FeatureX 10.0) 3)`, or one of the built-in rule/connector/helper forms described below.

### 1.2 Query form for `query`

Template:

    (: $proofVar typePattern $tvVar)

Meaning:

- The first slot must be a variable. Typical names are `$prf` or `$p`.
- `typePattern` is the proposition/rule/compound/helper pattern to search for.
- The truth-value slot is normally a variable such as `$tv`.
- Variables in `typePattern` retrieve bindings.

Examples:

    (: $prf (Dog fido) $tv)

    (: $prf (Dog $x) $tv)

    (: $prf (Path A C) $tv)

    (: $prf (And (P $x) (Compute + ($x 1) -> $y) (P $y)) $tv)

A query with a non-variable proof slot, such as `(: proof1 (Dog fido) $tv)`, is rejected.

---

## 2. Surface atoms, variables, and ordinary predicates

### Constants

Bare symbols such as `fido`, `alice`, `room1`, `A`, `countryA`, and `rectA` are constants. They match only themselves.

### Variables

Variables begin with `$`, for example:

    $x
    $person
    $room
    $tv
    $prf

Variables are pattern variables. In rules, shared variables connect premises and conclusions. In queries, variables retrieve bindings.

### Ordinary predicates

Any S-expression whose head is not a built-in special form can be used as an ordinary predicate or term:

    (Dog fido)
    (Person alice)
    (Owns alice dog1)
    (HeightDist group1 alice (PointMass 160.0))
    (AtTime (FeatureX 10.0) 3)

The chainer assigns no built-in semantics to such predicate names. Their meaning comes from asserted facts and rules.

---

## 3. Built-in operators and connectors

### 3.1 Proof atom envelope: `:`

Statement/query envelope:

    (: proof type tv)

For `add_atom`, this asserts a fact/rule/proposition with proof id and truth/value object. For `query`, this is the pattern returned by the reasoner.

---

### 3.2 Rule implication: `Implication`, `Premises`, `Conclusions`

Canonical rule syntax:

    (: ruleName
       (Implication
          (Premises premise1 premise2 ...)
          (Conclusions conclusion1 conclusion2 ...))
       (STV s c))

Semantic effect:

- The rule says that if all premises are provable, the conclusions can be derived.
- Premise truth values are combined conjunctively.
- The rule truth value is then applied to the premise truth to produce the derived conclusion truth.
- Variables shared between premises and conclusions are instantiated by premise matches.
- Multiple premises mean conjunction.
- Multiple conclusions are supported by listing several expressions inside `Conclusions`.

Example:

    (: r1
       (Implication
          (Premises (Parent $x $y) (Parent $y $z))
          (Conclusions (Grandparent $x $z)))
       (STV 1.0 1.0))

Multi-conclusion example:

    (: r2
       (Implication
          (Premises (Dog $x))
          (Conclusions (Animal $x) (Mammal $x)))
       (STV 1.0 1.0))

Recommended constraint: avoid conclusion-only variables unless you deliberately want generated existential-like terms. For NL translation, prefer variables in conclusions to also occur in premises, or use an explicit named entity constant.

---

### 3.3 Bidirectional implication: `BiImplication`

Syntax:

    (: ruleName
       (BiImplication
          (Premises left1 left2 ...)
          (Conclusions right1 right2 ...))
       (STV s c))

Semantic effect:

- Represents a two-way rule.
- The left side can derive the right side.
- The right side can derive the left side.
- Premises/conclusions use the same syntax as `Implication`.

Example:

    (: iff1
       (BiImplication
          (Premises (Bachelor $x))
          (Conclusions (And (Man $x) (Unmarried $x))))
       (STV 1.0 1.0))

---

### 3.4 Conjunction: `And`

Syntax:

    (And expr1 expr2 ...)

Semantic effect:

- In a rule/query premise position, all children must be provable.
- Truth strength is combined by product-like conjunction.
- Confidence is the minimum confidence of the children.
- In the default PLN logic, `And` also supports projection from asserted conjunctions, but projection of a child may require evidence for the other conjuncts. Do not rely on an asserted `(And A B)` alone as a simple replacement for asserting both `A` and `B`; if you want both facts, assert both facts explicitly or use a rule with multiple conclusions.

Rule premise example:

    (: r
       (Implication
          (Premises (And (A $x) (B $x)))
          (Conclusions (C $x)))
       (STV 1.0 1.0))

Equivalent and usually clearer rule premise form:

    (: r
       (Implication
          (Premises (A $x) (B $x))
          (Conclusions (C $x)))
       (STV 1.0 1.0))

Compound query example:

    (: $prf (And (A $x) (B $x)) $tv)

---

### 3.5 Disjunction: `Or`

Syntax:

    (Or expr1 expr2 ...)

Default PLN semantic effect:

- `Or` is a compound connective whose truth is computed with probabilistic-or style strength:
  `s(A or B) = s(A) + s(B) - s(A)*s(B)`.
- Confidence is the minimum child confidence.
- In the default PLN configuration, `Or` is not simple logical introduction: a fact `(A)` alone does not by itself make `(Or (A) (B))` provable.
- Use `Or` only when you want the chainer's PLN compound-disjunction behavior, not as a casual natural-language “maybe A or B” marker.

Predicate-logic configuration note:

- If the chainer is constructed with `logic_config="predicate_logic"`, `Or` behaves as an introduction-style disjunction: evidence for any child can prove the `Or` expression.
- Unless that configuration is explicitly used, assume default PLN behavior.

Example:

    (: $prf (Or (A) (B)) $tv)

---

### 3.6 Relative likelihood: `LikelierThan`

Syntax:

    (LikelierThan exprA exprB)

Semantic effect:

- Compares two propositions by their truth strengths.
- Produces a truth value with strength `max(0.0, strength(exprA) - strength(exprB))`.
- Confidence is the minimum of the two input confidences.
- It is a compound connective, not an ordering over numeric terms.

Example:

    (: $prf (LikelierThan (Rainy day1) (Sunny day1)) $tv)

---

### 3.7 Computation premise/query helper: `Compute`

Preferred syntax:

    (Compute function (arg1 arg2 ...) -> out)

Also accepted in some contexts:

    (Compute function (arg1 arg2 ...) out)

Semantic effect:

- Evaluates `function` on the argument list.
- Unifies the result with `out`.
- Common use: arithmetic binding in a rule premise or compound query.
- The computation itself contributes truth `(STV 1.0 1.0)` unless it is being used through a truth-producing formula.

Examples:

    (Compute + ($a $b) -> $sum)

    (Compute + ($t 1) -> $nextT)

Rule example:

    (: r
       (Implication
          (Premises
             (AtTime (FeatureX $x) $t)
             (Compute + ($t 1) -> $t1)
             (AtTime (FeatureY $y) $t1))
          (Conclusions (NextFeaturePair $x $y)))
       (STV 1.0 1.0))

Compound query example:

    (: $prf (And (P $x) (Compute + ($x 1) -> $y) (P $y)) $tv)

Recommendation: for query-time computation, place `Compute` as a direct child of an `And` query with the facts that bind its inputs.

---

### 3.8 Truth complement: `Not`

Syntax:

    (Not expr)

Semantic effect:

- This is truth-value negation, not negation-as-failure.
- It first requires evidence for `expr`.
- If `expr` has truth `(STV s c)`, `(Not expr)` has truth `(STV (1 - s) c)`.
- If there is no evidence for `expr`, `Not` does not by itself succeed merely because the fact is absent.

Example:

    (: r
       (Implication
          (Premises (Not (Allowed $x)))
          (Conclusions (Disallowed $x)))
       (STV 1.0 1.0))

Use this only when a complemented uncertain truth value is intended.

---

### 3.9 Distribution comparison: `GreaterThan` and `>`

Syntax forms:

    (GreaterThan dist threshold)
    (> dist threshold)
    (GreaterThan distA distB)
    (> distA distB)

Semantic effect:

- These are distribution comparisons.
- `dist` should be a distribution value such as one produced by `PointMass`, `ParticleFromNormal`, `ParticleFromPairs`, `MapDist`, `Map2Dist`, `AverageDist`, or `FoldAllValue`.
- With a numeric threshold, the result is an STV whose strength is the probability that the distribution is greater than the threshold.
- With two distributions, the result is an STV whose strength is the probability that a sample from `distA` is greater than a sample from `distB`.
- Confidence is derived from the underlying distribution evidence.
- This is not a general scalar comparison predicate for arbitrary ordinary numbers.

Example:

    (: r
       (Implication
          (Premises
             (HeightDist $person $heightDist)
             (GreaterThan $heightDist 170.0))
          (Conclusions (Tall $person)))
       (STV 1.0 1.0))

Distribution-vs-distribution example:

    (: r
       (Implication
          (Premises
             (CountryHeightDist countryA $distA)
             (CountryHeightDist countryB $distB)
             (GreaterThan $distA $distB))
          (Conclusions (Taller countryA countryB)))
       (STV 1.0 1.0))

---

### 3.10 Fold aggregation: `FoldAll`

Syntax:

    (FoldAll pattern value init fold-fn -> out)

Semantic effect:

- Finds all matches of `pattern`.
- For each match, extracts/evaluates `value`.
- Folds those values starting from `init` using `fold-fn`.
- Binds the aggregate to `out`.
- The helper itself contributes `(STV 1.0 1.0)`.

Example: sum scores.

    (: $prf
       (FoldAll
          (Score $name $n)
          $n
          0
          (|-> ($acc $elem) (+ $acc $elem))
          ->
          $total)
       $tv)

As a rule premise:

    (: r
       (Implication
          (Premises
             (Group $g)
             (FoldAll (MemberScore $g $m $score)
                      $score
                      0
                      (|-> ($acc $elem) (+ $acc $elem))
                      ->
                      $total))
          (Conclusions (TotalScore $g $total)))
       (STV 1.0 1.0))

---

### 3.11 Fold over truth values: `FoldAllValue`

Syntax:

    (FoldAllValue pattern init fold-fn -> out)

Semantic effect:

- Finds all matches of `pattern`.
- For each matched fact, uses that fact's truth value as the folded element.
- Starts with `init`, applies `fold-fn`, and binds the result to `out`.
- Commonly used to build a count distribution from uncertain membership facts.

Example:

    (: cntRule
       (Implication
          (Premises
             (Room $room)
             (FoldAllValue
                (In $room $kid)
                (ParticleFromPairs ((0 1.0)))
                ParticleAddBernoulliFromSTV
                ->
                $countDist))
          (Conclusions (CntKidIn $room $countDist)))
       (STV 1.0 0.8))

Then threshold the resulting distribution:

    (: playRule
       (Implication
          (Premises
             (Room $room)
             (CntKidIn $room $cnt)
             (GreaterThan $cnt 1))
          (Conclusions (PlayTogetherIn $room)))
       (STV 1.0 0.75))

---

### 3.12 Distribution map helper: `MapDist`

Syntax:

    (MapDist function (DistFact ... $inDist) $inDist -> $outDist)

Semantic effect:

- Matches a fact pattern containing an input distribution.
- Applies a unary function to the distribution.
- Binds the transformed distribution to `$outDist`.
- Used in rule premises.

Example:

    (: r
       (Implication
          (Premises
             (MapDist sqrt (AreaDist $x $areaDist) $areaDist -> $sideDist))
          (Conclusions (SideDist $x $sideDist)))
       (STV 1.0 1.0))

---

### 3.13 Binary distribution map helper: `Map2Dist`

Syntax:

    (Map2Dist function
       (DistFactA ... $distA) $distA
       (DistFactB ... $distB) $distB
       ->
       $outDist)

Semantic effect:

- Matches two distribution-valued facts.
- Applies a binary function pointwise/particlewise to combine the two distributions.
- Binds the resulting distribution to `$outDist`.

Example: rectangle area distribution.

    (: areaRule
       (Implication
          (Premises
             (Rectangle $rect)
             (Map2Dist *
                (LengthDist $rect $lengthDist)
                $lengthDist
                (WidthDist $rect $widthDist)
                $widthDist
                ->
                $areaDist))
          (Conclusions (AreaDist $rect $areaDist)))
       (STV 1.0 1.0))

---

### 3.14 Average distribution helper: `AverageDist`

Syntax:

    (AverageDist (DistFactPattern ... $inDist) $inDist -> $outDist)

Semantic effect:

- Matches all distribution-valued facts satisfying the pattern.
- Computes an average distribution over the matched distributions.
- Binds the result to `$outDist`.

Example:

    (: avgRule
       (Implication
          (Premises
             (Group $g)
             (AverageDist
                (HeightDist $g $person $heightDist)
                $heightDist
                ->
                $avgDist))
          (Conclusions (AvgHeightDist $g $avgDist)))
       (STV 1.0 1.0))

---

### 3.15 Distribution constructors and operations

Supported distribution/value constructors:

    (NatDist ((value probability) ...))
    (FloatDist ((value probability) ...))
    (ParticleDist ref)
    (ParticleDist ref scale)
    (PointMass x)
    (ParticleFromNormal mu sigma)
    (ParticleFromPairs ((x1 w1) (x2 w2) ...))

Recommended constructors:

- `(PointMass x)` for an exact numeric value represented as a degenerate distribution.
- `(ParticleFromNormal mu sigma)` for an uncertain normal-like numeric value.
- `(ParticleFromPairs ((x1 w1) (x2 w2) ...))` for explicit weighted samples.

Distribution transformation functions:

    (ParticleMap function particleDist)
    (ParticleMap2 function particleDistA particleDistB)

Distribution truth formulas:

    (DistGreaterThanFormula dist threshold)
    (DistGreaterThanDistFormula distA distB)

Common fold function:

    (ParticleAddBernoulliFromSTV particleDist stv)

Recommended modeling pattern for numeric measurements:

    (: h1 (HeightDist g1 alice (PointMass 160.0)) (STV 1.0 1.0))

    (: h2 (HeightDist g1 bob (ParticleFromNormal 170.0 2.0)) (STV 1.0 1.0))

That is: put the uncertain numeric value as a distribution term in the proposition, and keep the proposition's existence/truth in an `STV`.

---

## 4. Truth values and value uncertainty

### 4.1 Simple truth value: `STV`

Syntax:

    (STV strength confidence)

Meaning:

- `strength` is belief/probability-like mass, normally in `[0, 1]`.
- `confidence` is evidence/reliability, normally in `[0, 1]`.

Example:

    (: d1 (Dog fido) (STV 1.0 0.9))

Interpretation: the proposition `(Dog fido)` is strongly believed, with confidence `0.9`.

Important: `STV` is for uncertainty about whether a proposition is true. Do not use `STV` strength to encode a numeric measurement such as height, age, count, or price.

### 4.2 Distribution values

Supported forms:

    (NatDist ((value probability) ...))
    (FloatDist ((value probability) ...))
    (ParticleDist ref)
    (ParticleDist ref scale)
    (PointMass x)
    (ParticleFromNormal mu sigma)
    (ParticleFromPairs ((x1 w1) (x2 w2) ...))

Use distributions for value uncertainty.

Examples:

    (: h1 (HeightDist g1 alice (PointMass 160.0)) (STV 1.0 1.0))

    (: h2 (HeightDist g1 bob (ParticleFromNormal 170.0 2.0)) (STV 1.0 1.0))

    (: count1 (CountDist g1) (NatDist ((0 0.5) (1 0.5))))

Although distribution forms are accepted as the third `tv` slot of a statement, the most useful modeling idiom for measurements is usually to keep the `tv` slot as an `STV` and place the distribution in the proposition term.

## 5. Rule composition patterns

### 5.1 Ground fact

    (: fact1 (Predicate arg1 arg2) (STV 1.0 1.0))

Example:

    (: f1 (Dog fido) (STV 1.0 1.0))

### 5.2 Unary classification fact

    (: fact1 (Class entity) (STV s c))

Example:

    (: f1 (Person alice) (STV 1.0 1.0))

### 5.3 Binary relation fact

    (: fact1 (Relation subject object) (STV s c))

Example:

    (: f1 (Owns alice dog1) (STV 1.0 1.0))

### 5.4 Canonical if-then rule

    (: ruleName
       (Implication
          (Premises premise)
          (Conclusions conclusion))
       (STV s c))

Example:

    (: r1
       (Implication
          (Premises (Dog $x))
          (Conclusions (Animal $x)))
       (STV 1.0 1.0))

### 5.5 Multi-premise rule

Preferred syntax:

    (: ruleName
       (Implication
          (Premises premise1 premise2 ...)
          (Conclusions conclusion))
       (STV s c))

Example:

    (: r1
       (Implication
          (Premises (Parent $x $y) (Parent $y $z))
          (Conclusions (Grandparent $x $z)))
       (STV 1.0 1.0))

Equivalent compound-premise style:

    (: r1
       (Implication
          (Premises (And (Parent $x $y) (Parent $y $z)))
          (Conclusions (Grandparent $x $z)))
       (STV 1.0 1.0))

The explicit multiple-premise form is clearer for NL translation.

### 5.6 Multi-conclusion rule

    (: ruleName
       (Implication
          (Premises premise)
          (Conclusions conclusion1 conclusion2 ...))
       (STV s c))

Example:

    (: r1
       (Implication
          (Premises (Dog $x))
          (Conclusions (Animal $x) (Mammal $x)))
       (STV 1.0 1.0))

### 5.7 Rule with arithmetic/computation

    (: ruleName
       (Implication
          (Premises
             factPattern
             (Compute function (args...) -> $out)
             anotherFactPattern)
          (Conclusions conclusion))
       (STV s c))

Example:

    (: r
       (Implication
          (Premises
             (AtTime (FeatureX $x) $t)
             (Compute + ($t 1) -> $t1)
             (AtTime (FeatureY $y) $t1))
          (Conclusions (NextPair $x $y)))
       (STV 1.0 1.0))

### 5.8 Rule over uncertain numeric values

Use distribution-valued facts, then compare or transform distributions.

Example:

    (: tallRule
       (Implication
          (Premises
             (HeightDist $person $heightDist)
             (GreaterThan $heightDist 170.0))
          (Conclusions (Tall $person)))
       (STV 1.0 1.0))

### 5.9 Aggregation/count rule

Example: count uncertain members in a room.

    (: cntRule
       (Implication
          (Premises
             (Room $room)
             (FoldAllValue
                (In $room $kid)
                (ParticleFromPairs ((0 1.0)))
                ParticleAddBernoulliFromSTV
                ->
                $cnt))
          (Conclusions (CntKidIn $room $cnt)))
       (STV 1.0 0.8))

Then use the aggregate:

    (: gtRule
       (Implication
          (Premises
             (CntKidIn $room $cnt)
             (GreaterThan $cnt 1))
          (Conclusions (ManyKidsIn $room)))
       (STV 1.0 0.75))

### 5.10 Distribution composition rule

Example: area from length and width.

    (: areaRule
       (Implication
          (Premises
             (Rectangle $rect)
             (Map2Dist *
                (LengthDist $rect $lengthDist)
                $lengthDist
                (WidthDist $rect $widthDist)
                $widthDist
                ->
                $areaDist))
          (Conclusions (AreaDist $rect $areaDist)))
       (STV 1.0 1.0))

### 5.11 Average distribution rule

    (: avgRule
       (Implication
          (Premises
             (Group $g)
             (AverageDist
                (HeightDist $g $person $heightDist)
                $heightDist
                ->
                $avgDist))
          (Conclusions (AvgHeightDist $g $avgDist)))
       (STV 1.0 1.0))

### 5.12 Equivalence / if-and-only-if rule

    (: iffRule
       (BiImplication
          (Premises leftExpr)
          (Conclusions rightExpr))
       (STV s c))

Example:

    (: r
       (BiImplication
          (Premises (Sibling $x $y))
          (Conclusions (Sibling $y $x)))
       (STV 1.0 1.0))

Use `BiImplication` when the NL says “if and only if”, “equivalent to”, or a symmetric definition is intended.

## 6. Query patterns and constraints

### 6.1 Required query envelope

Always use:

    (: $prf typePattern $tv)

The proof slot must be a variable.

Valid:

    (: $prf (Dog fido) $tv)

Invalid:

    (: proof1 (Dog fido) $tv)

Also invalid for the Python API:

    !(query 10 kb (: $prf (Dog fido) $tv))

### 6.2 Ground fact existence

Ask whether a specific proposition can be proved:

    (: $prf (Dog fido) $tv)

If the returned list is non-empty, the chainer found at least one proof.

### 6.3 Binding retrieval

Use variables in the proposition:

    (: $prf (Dog $x) $tv)

    (: $prf (Owns alice $pet) $tv)

The returned proof atoms include the instantiated proposition and truth value.

### 6.4 Retrieve truth values

Use a variable in the truth slot:

    (: $prf (Dog fido) $tv)

The result contains the derived or asserted truth value.

A more constrained truth-value pattern may be syntactically usable, but the robust and documented pattern is to use `$tv`.

### 6.5 Compound-expression query

Conjunction query:

    (: $prf (And (A $x) (B $x)) $tv)

Disjunction query:

    (: $prf (Or (A) (B)) $tv)

Computation inside compound query:

    (: $prf (And (P $x) (Compute + ($x 1) -> $y) (P $y)) $tv)

Recommendation: when a query needs computation, put `Compute` as a direct child of an `And` query with surrounding predicates that bind its inputs.

### 6.6 Query an aggregate directly

`FoldAll` can be the queried type:

    (: $prf
       (FoldAll
          (Score $name $n)
          $n
          0
          (|-> ($acc $elem) (+ $acc $elem))
          ->
          $total)
       $tv)

This retrieves an aggregate binding such as `$total`.

### 6.7 Query derived distribution values

Example:

    (: $prf (AvgHeightDist g1 $avgDist) $tv)

Then the returned proposition contains a distribution term bound in place of `$avgDist`.

### 6.8 Query a rule as data

Rules themselves can be queried:

    (: $prf
       (Implication
          (Premises (A))
          (Conclusions (B)))
       $tv)

Open rule query:

    (: $prf
       (Implication
          (Premises ($premise))
          (Conclusions (B)))
       $tv)

This is useful only when the user asks about rules or implications themselves. For normal fact questions, query the conclusion proposition instead.

### 6.9 Wildcard `#`

A wildcard-like `#` can appear in some query patterns to match without binding, for example inside rule-pattern queries:

    (: $prf
       (Implication
          (Premises (#))
          (Conclusions (B)))
       $tv)

For NL translation, prefer named variables such as `$x` when a binding may be useful. Use `#` only when the matched content should be ignored.

### 6.10 Syntactically valid but discouraged query patterns

Avoid these unless explicitly needed:

- `(: $prf $type $tv)` — too broad; may ask for everything.
- Queries with many unconstrained variables — may be expensive or uninformative.
- Direct `Or` queries in default PLN when the desired semantics is ordinary “A or B from A”; default PLN does not use simple or-introduction.
- Direct `Not` queries when the intended meaning is “not known”; `Not` is truth complement, not absence of proof.
- Queries with a fixed proof id in the first slot — rejected by the Python validator.

## 7. Quantification and scope

### 7.1 Universal quantification

There is no explicit surface `ForAll` operator.

Rules with variables behave like universally applicable patterns over matching substitutions. For example:

    (: r
       (Implication
          (Premises (Dog $x))
          (Conclusions (Animal $x)))
       (STV 1.0 1.0))

This should be used for NL statements like “all dogs are animals” or “if someone is a dog, they are an animal”.

### 7.2 Existential quantification

There is no dedicated surface `Exists` operator.

For NL “there exists ...” cases, use one of these strategies:

1. If the entity is known or should be introduced, create a fresh constant and assert facts about it.

       (: e1 (Person person_001) (STV 1.0 1.0))
       (: e2 (Owns alice person_001) (STV 1.0 1.0))

2. If the user is asking whether some entity exists, use a query variable.

       (: $prf (Person $x) $tv)

Avoid writing a conclusion variable that appears nowhere in the premises as a general existential representation; it is not a clean user-facing quantifier idiom.

### 7.3 Cardinal quantifiers

There are no dedicated surface operators for `exactly N`, `at least N`, `at most N`, `most`, `many`, `few`, or `majority`.

Represent cardinal and vague quantifier meanings indirectly:

- Aggregate with `FoldAll` or `FoldAllValue`.
- Represent uncertain counts as distributions.
- Compare distributions with `GreaterThan`.
- Encode the threshold chosen for vague terms in a domain-specific rule.

Example for “more than one kid is in the room”:

    (: cntRule
       (Implication
          (Premises
             (Room $room)
             (FoldAllValue
                (In $room $kid)
                (ParticleFromPairs ((0 1.0)))
                ParticleAddBernoulliFromSTV
                ->
                $cnt))
          (Conclusions (CntKidIn $room $cnt)))
       (STV 1.0 0.8))

    (: manyRule
       (Implication
          (Premises
             (CntKidIn $room $cnt)
             (GreaterThan $cnt 1))
          (Conclusions (ManyKidsIn $room)))
       (STV 1.0 0.75))

For “most” or “majority”, create an explicit aggregate/threshold rule appropriate to the domain, e.g. compare a count distribution to half of a total count distribution. There is no built-in natural-language majority operator.

### 7.4 Quantifier scope and negation

Scope is represented only by S-expression structure and variable sharing.

- Variables shared in a rule connect premises and conclusions.
- Variables in a query are retrieval variables.
- `(Not expr)` scopes only over `expr`.
- There is no nested quantifier syntax.
- Truth values do not create quantifier scope; they only represent uncertain truth or uncertain values.

For negated quantifier-like NL, do not try to encode scope with a special quantifier. Instead, create explicit predicates/rules that capture the intended domain meaning.

## 8. Entity identity and representation

### 8.1 Identity model

The chainer has no built-in real-world entity identity system. Symbols are syntactic labels:

- `alice` matches `alice`.
- `Alice` and `alice` are different symbols.
- `paris_france` and `paris_texas` are different symbols.
- Two people named “Ben” are the same only if the same constant is used for both.

There is no built-in `sameAs`, name resolution, string normalization, or entity linking.

### 8.2 Recommended entity IDs

For named entities from NL, the translator should use stable, unique constants whenever possible:

    ben_person_001
    paris_france_city
    paris_texas_city
    apple_company
    apple_fruit_kind

Avoid using ambiguous bare names such as `Ben` or `Paris` when the NL context could refer to multiple entities.

### 8.3 Names as ordinary facts

If it is useful to preserve a surface name, add ordinary naming facts. These predicates have no built-in semantics unless rules are added for them.

Example:

    (: n1 (Name ben_person_001 Ben) (STV 1.0 1.0))

    (: c1 (City paris_france_city) (STV 1.0 1.0))
    (: n2 (Name paris_france_city Paris) (STV 1.0 1.0))

`Name`, `City`, and similar predicates are ordinary user predicates.

### 8.4 Class membership idioms

The examples use unary predicates for class membership:

    (: f1 (Dog fido) (STV 1.0 1.0))
    (: f2 (Person alice) (STV 1.0 1.0))
    (: f3 (Room room1) (STV 1.0 1.0))

An `Instance` or `Inheritance` predicate can be used if the application defines it, but there is no special built-in semantics for those names. Unary class predicates are the simplest idiom.

### 8.5 Pronouns

There is no built-in convention for first-person, second-person, or discourse pronouns such as “I”, “we”, “you”, “he”, “she”, or “they”.

The NL layer should resolve pronouns before generating PeTTaChainer expressions. If the referent is unknown, do not assert a fact about a literal constant like `I` or `you` unless the surrounding application has explicitly assigned such a symbol.

Possible application-level convention, if context provides it:

    current_speaker
    current_addressee
    group_current_speaker

But these are ordinary constants, not built-ins.

## 9. Practical generation guidelines

1. Always emit the inner proof atom only:
       (: proof type tv)
   for statements, and
       (: $prf typePattern $tv)
   for queries.

2. Use `STV` for truth uncertainty:
       (STV 1.0 1.0)
       (STV 0.7 0.8)

3. Use distribution terms for uncertain numeric values:
       (PointMass 10.0)
       (ParticleFromNormal 10.0 1.0)
       (ParticleFromPairs ((1 0.25) (2 0.75)))

4. Prefer explicit multi-premise rules over nested `And` when translating “if A and B then C”:
       (Premises (A $x) (B $x))

5. Use `Not` only for truth complement, not for “unknown” or “not found”.

6. Use `GreaterThan` only for distribution threshold/comparison reasoning.

7. Use `FoldAll`/`FoldAllValue` for counts, totals, and aggregate-derived rules.

8. Use unique entity constants; add ordinary `Name` facts if the original surface name matters.

9. Avoid unsupported quantifier words as operators. There is no `ForAll`, `Exists`, `Most`, `Many`, `Few`, or `Majority` built-in. Encode those meanings with rules, variables, aggregation, and thresholds.
